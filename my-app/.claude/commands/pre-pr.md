PR을 올리기 전 점검을 해 줘. base 브랜치 인자: `$ARGUMENTS` (비어 있으면 `main`을 사용)

이 명령은 커밋, 푸시, PR 생성을 하지 않아. 점검 결과와 PR 초안만 만들어. 커밋이나 PR 생성은 사용자가 따로 요청할 때만 해.

## 1. 상태 확인

- `git status`와 `git branch --show-current`로 현재 브랜치와 커밋되지 않은 변경을 확인.
- 현재 브랜치가 base 브랜치와 같으면 멈추고 사용자에게 알려줘.
- 커밋되지 않은 변경이 있으면 목록을 보여주고, 이 명령은 그 변경을 포함해서 점검한다고 알려줘.

## 2. 자동 점검 (순서대로)

1. `npm run lint`
2. `npx tsc --noEmit`
3. `npm run build`
4. `npx playwright test`
   - 브라우저가 없으면 `npx playwright install chromium`을 안내하고, 설치 여부는 사용자에게 확인.
   - 개발 서버가 필요한 테스트라면 `npm run build && npm run start`로 띄운 뒤 실행할지 사용자에게 물어봐.

각 단계가 실패하면 나머지 단계는 계속 진행하고, 마지막에 실패 목록을 한꺼번에 보고해. 실패 원인은 출력 원문에서 핵심 줄만 인용해.

## 3. 변경 분석

- `git diff <base>...HEAD`와 `git diff`(미커밋 변경)를 함께 읽어.
- 다음을 특별히 확인하고 보고:
  - `.env`, 키, 토큰 등 비밀 값이 포함되지 않았는지.
  - `console.log`, `TODO`, 주석 처리된 코드가 남아 있지 않은지.
  - `components/ui/` 변경이 있다면 Base UI 기반 규칙을 지켰는지.
  - `package.json`, `package-lock.json` 변경이 의도한 것인지.

## 4. PR 설명 초안

다음 형식으로 작성해 줘:

```
## 요약
- 변경 사항을 한두 줄로

## 변경 내용
- 주요 파일과 변경 이유

## 점검
- [ ] lint
- [ ] tsc
- [ ] build
- [ ] playwright (실행했다면 결과)

## 확인이 필요한 부분
- 리뷰어가 집중해서 볼 곳
```

- 실제로 실행하지 않은 항목은 체크하지 말고 "미실행"이라고 써.
- PR 설명 끝에 세션에서 지정된 attribution 줄을 붙여.

## 5. 최종 보고

- 점검 결과 표 (단계, 통과/실패, 한 줄 메모)
- 발견한 위험 요소
- PR 설명 초안 (마크다운 코드 블록)
- 다음 단계 제안: 커밋 → 푸시 → PR 생성 중 어디까지 진행할지 물어보기
